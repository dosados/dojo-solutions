# Результаты экспериментов

Я занял **24-е место из 320 участников**. Ниже — результаты отдельных экспериментов; команды и настройки сохранены в [журнале](../experiments/JOURNAL.md).

## Task 1: перенос промптов между доменами

4 июня перебраны 16 вариантов промпта. На OPUS val из 300 предложений English rules prompt дал **28.42 macro BLEU** против **26.97** у baseline: прирост **1.45**. На собственном абзацном dev эффект был другим: оптимизация под отдельные предложения не переносилась напрямую на абзацы.

На первых 20 абзацах собственного dev Gemma с промптом v1 дала 64.60 BLEU, базовая TranslateGemma — 35.50. Few-shot примеры для этого промпта взяты из того же dev, поэтому для независимой оценки нужен отдельный набор.

Текущий `task-1/submission/solution.py` использует baseline-промпт, без постобработки, beam=3 и length penalty=0.8. Промпт с результатом 28.42 сохранён среди экспериментальных вариантов.

## Task 2: адаптация к малоресурсному языку

31 мая TranslateGemma-4B после CLM → SFT получила **8.7 BLEU на закрытом тесте из 515 примеров**. Посылка прошла по времени после ускорения inference. Локальная оценка примерно 21 заметно переоценила закрытый результат.

4 июня на локальном dev из 500 примеров для имеющихся merged-весов измерены варианты декодирования:

| Режим | Macro BLEU | Время |
|---|---:|---:|
| Greedy | 25.154 | 128.2 с |
| Beam=2, lp=0.8 | 26.065 | 205.3 с |
| Beam=3, lp=0.6 | 26.326 | 325.5 с |
| Beam=3, lp=0.8 | **26.401** | 327.3 с |
| Beam=3, lp=1.0 | 26.308 | 326.5 с |

Я выбрал beam=3, lp=0.8: **+1.247 BLEU** при увеличении времени в **2,55 раза** относительно greedy. Замеры сделаны на моей GPU. Этот режим включён в Task 2 / TranslateGemma; его балл на закрытом тесте не записан.

При настройке найден и исправлен в конкурсном TranslateGemma-коде срез декодируемых токенов при left padding: нужно удалять общую padded длину prompt, а не индивидуальную длину исходной строки. Сопоставление batch=40 и batch=1 после исправления дало близкие оценки на 40 примерах и не содержало обнаруженных ранее фрагментов prompt.

## Что ограничивает воспроизведение

- Ссылки на конкурсные RU–AB корпуса не сохранились. Собственный абзацный dev также не опубликован.
- В Git нет обученных адаптеров/merged-весов. Базовые модели можно скачать, обученное состояние нужно восстановить обучением или из собственной копии.
- Не зафиксированы все ревизии Hub, окружения и точная связь каждого локального каталога весов с финальной посылкой.
- Dev-наборы создавались разными скриптами; возможны пересечения с train. Для нового сравнения нужно зафиксировать одно разбиение и проверить пересечения по текстам.
