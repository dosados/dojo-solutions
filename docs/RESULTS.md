# Результаты и ограничения

**24-е место из 320 участников (top 7,5%)** — результат участия, сообщённый автором. Снимок таблицы лидеров и прямая ссылка на неё в локальных материалах отсутствуют. Репозиторий сохраняет отдельно конкретные измерения качества и скорости, не подменяя ими место в рейтинге.

Все числа ниже взяты из [experiments/JOURNAL.md](../experiments/JOURNAL.md). Они получены в разных условиях и не являются единым сравнительным benchmark.

## Task 1: перенос промптов между доменами

4 июня перебраны 16 вариантов промпта. На OPUS val из 300 предложений English rules prompt дал **28.42 macro BLEU** против **26.97** у baseline: прирост **1.45**. На собственном абзацном dev эффект был другим: оптимизация под отдельные предложения не переносилась напрямую на абзацы.

2 июня в другом сравнении на первых 20 локальных абзацах Gemma с промптом v1 дала 64.60 против 35.50 у базовой TranslateGemma. Это отдельный эксперимент с собственной конфигурацией. Few-shot примеры в истории брались из частей локального dev, поэтому такую оценку нельзя представлять как независимую проверку обобщения.

Текущий `task-1/submission/solution.py` использует baseline-промпт, без постобработки, beam=3 и length penalty=0.8. Поэтому 28.42 — результат исследовательского промпта, а не автоматически результат текущего CLI по умолчанию.

## Task 2: адаптация к малоресурсному языку

31 мая TranslateGemma-4B после CLM → SFT получила **8.7 BLEU на закрытом тесте из 515 примеров**. Посылка прошла по времени после ускорения inference. Локальная оценка примерно 21 заметно переоценила закрытый результат.

4 июня на локальном dev из 500 примеров для имеющихся merged-весов измерены варианты декодирования:

| Режим | Macro BLEU | Время |
|---|---:|---:|
| Greedy | 25.154 | 128.2 с |
| Beam=2, lp=0.8 | 26.065 | 205.3 с |
| Beam=3, lp=0.6 | 26.326 | 325.5 с |
| Beam=3, lp=0.8 | **26.401** | 327.3 с |
| Beam=3, lp=1.0 | 26.308 | 326.5 с |

Выбран beam=3, lp=0.8: **+1.247 BLEU**, примерно **2,55×** времени относительно greedy. Значения относятся к локальному эксперименту на GPU автора; нельзя выдавать их за скорость на конкурсной L4. Текущая посылка Task 2 / TranslateGemma содержит этот режим, но подтверждённого закрытого балла этой последней версии в журнале нет.

При настройке найден и исправлен в конкурсном TranslateGemma-коде срез декодируемых токенов при left padding: нужно удалять общую padded длину prompt, а не индивидуальную длину исходной строки. Сопоставление batch=40 и batch=1 после исправления дало близкие оценки на 40 примерах и не содержало обнаруженных ранее фрагментов prompt.

## Что ограничивает воспроизведение

- Ссылки на конкурсные RU–AB корпуса не сохранились. Собственный абзацный dev также не опубликован.
- В Git нет обученных адаптеров/merged-весов. Базовые модели можно скачать, обученное состояние нужно восстановить обучением или из собственной копии.
- Не зафиксированы все ревизии Hub, окружения и точная связь каждого локального каталога весов с финальной посылкой.
- Исторические dev splits создавались разными инструментами. Возможны пересечения train/dev; локальные оценки не доказывают качество на независимом тесте.
- Наличие конфига NLLB или Gemma не означает, что эта линия была лучшей посылкой. В репозитории сохранены и исследовательские альтернативы.

Для нового исследования фиксируйте версии моделей и библиотек, единственное разбиение данных, состав checkpoint, генерационные настройки и результаты на отдельном тесте. Исторические значения выше сохраняются с их исходным контекстом.
