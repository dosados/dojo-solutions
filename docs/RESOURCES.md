# Модели, данные и восстановление

В Git хранятся исходники, конфиги и документация. Веса, токенизаторы из checkpoint-каталогов, корпуса, кэши, ZIP и результаты запусков исключены. Таблица ниже описывает, откуда восстановить каждый тип ресурса.

## Базовые модели

| Режим | Ресурс | Команда из корня |
|---|---|---|
| Gemma, задачи 1/2 | [google/gemma-4-E2B-it](https://huggingface.co/google/gemma-4-E2B-it) | `python dojo.py download --task 1 --model gemma` |
| TranslateGemma, задачи 1/2 | [google/translategemma-4b-it](https://huggingface.co/google/translategemma-4b-it) | `python dojo.py download --task 2 --model translate` |
| NLLB, задача 2 | [facebook/nllb-200-3.3B](https://huggingface.co/facebook/nllb-200-3.3B) | `python dojo.py download --task 2 --model nllb` |

`--task` выбирает каталог задачи. `--weights PATH` меняет каталог загрузки; `--revision COMMIT` фиксирует версию Hub. Без revision используется изменяемая ветка `main`, поэтому исторические веса не гарантируются. По завершении создаётся `dojo-source.json`. Загрузка в непустой каталог отклоняется, чтобы не перезаписать своё дообучение. Для возобновления прерванного скачивания используйте исходный `task-*/download_weights*.py` только в каталоге, предназначенном для этой базовой модели.

Страницы моделей доступны на момент оформления. Сверяйтесь с model card, лицензией и требованиями доступа каждого ресурса. Исторические скрипты могли запрашивать принятие условий Google; при необходимости выполните `hf auth login`. Новые ревизии моделей могут требовать другой версии Transformers: для исходного решения сохранён контейнерный pin `5.5.0`, а не автоматическая миграция алгоритма.

## Датасеты

| Ресурс | Источник | Подготовка |
|---|---|---|
| OPUS-100 EN–RU | [Helsinki-NLP/opus-100](https://huggingface.co/datasets/Helsinki-NLP/opus-100), конфигурация `en-ru` | `task-1/scripts/download_opus100.py`, затем `convert_datasets.py --skip-self` |
| Русский монокорпус | [misterkirill/ru-wikipedia](https://huggingface.co/datasets/misterkirill/ru-wikipedia) | `task-2/download_ru_wikipedia.py` |
| Параллельный RU–AB корпус конкурса | Организаторы; ссылка была в интерфейсе задачи B на Yandex Contest | Вручную: `task-2/data/ab-ru-parallel.csv`, UTF-8 CSV со столбцами `ru,ab` |
| Абхазский монокорпус конкурса | Организаторы; ссылка была в интерфейсе задачи B на Yandex Contest | Вручную: `task-2/data/ab-mono.txt`, UTF-8, текст по строкам |
| Собственный абзацный EN–RU dev | Локальные материалы автора, публичная ссылка не сохранена | Для новых экспериментов используйте свой JSONL с `rid,src,ref` или OPUS |

**Прямые URL двух конкурсных корпусов не сохранены в исходниках.** В [копии условия](../task-2/docs/SPECS.md) остался текст «ссылка на Яндекс Диск» без адреса. Автозагрузка этих файлов из доступного репозитория невозможна; ссылку на конкретный конкурс также нельзя восстановить из сохранённого условия. Для точного повторения нужны оригинальные ресурсы из аккаунта участника или от организаторов. Подставлять другой корпус под прежнее название и метрики нельзя.

Task 1 работает с открытым OPUS и без локального авторского dev. Task 2 baseline inference доступен после загрузки базовых весов; повторное обучение требует RU–AB корпуса. Отсутствие конкурсных данных не блокирует изучение исходников и запуск на собственных данных подходящего формата.

## Обученные артефакты

Публичной ссылки на авторские LoRA-адаптеры и merged-веса нет. `download` получает **базовую модель**, не checkpoint с конкурсным BLEU. Восстановление обученной версии: исходный корпус → указанные CLM/SFT-конфиги → адаптер → merge с исходной базой. Численно идентичный результат не гарантируется без исходных ревизий, окружения, checkpoint и данных.

Перед удалением локальной папки отдельно сохраните нужные `runs/**/final`, `best_eval`, незавершённые checkpoints и уникальные `submission*/weights*`, если хотите сохранить именно обученные состояния. Они не восстановятся одним `git clone`. Это особенно относится к `weights_merged_contest_8p7_bleu`: название отражает локальную историю, а не удалённый источник скачивания.

Код и конфиги можно восстановить из Git; базовые веса и OPUS — из Hub. Корпуса без сохранённых URL, локальный dev и обученные checkpoints требуют отдельной копии или повторного обучения. Данная публикация не удаляет локальные файлы.
